# Настройки и контракт диагностики

## Два разных файла

`assets/project.example.json` — пример организационных настроек/исходных данных. Его заполняют для конкретной квартиры приватно. Он не является штатным файлом RemPlanner и не является входом валидатора.

Валидатор принимает отдельный **нормализованный** JSON геометрии. Извлечение из конкретного плана — отдельная проверяемая работа, а не встроенная возможность этой версии. Не называть поддержкой `.plan` простое чтение JSON.

## Нормализованный вход v1

```json
{
  "schema_version": 1,
  "units": "cm",
  "boundary": [[0,0],[400,0],[400,300],[0,300]],
  "obstacles": [{"id":"column-a","polygon":[[180,80],[220,80],[220,120],[180,120]]}],
  "graphs": [{
    "id":"circuit-a",
    "geometry":"polyline",
    "vertices":[{"id":"v1","point":[50,50],"anchor_id":"point-a"},{"id":"v2","point":[150,50]}],
    "matrix":[[null,1],[1,null]]
  }],
  "points":[{"id":"point-a","point":[50,50],"role":"room_socket","height_cm":30}],
  "doors":[{"id":"door-a","a":[0,100],"b":[0,190]}],
  "preferences":{"heights_cm":{"room_socket":30}},
  "required_facts":{"protective_earthing_verified":null,"supply_data_verified":null}
}
```

Это синтетический пример, не готовый электрический проект. `required_facts` содержит лишь документально установленные факты или `null`. Не ставить `true` ради зелёного отчёта. Для работы с реальной квартирой добавлять необходимые исходные факты из domain-чеклистов; пустой список не подтверждает их наличие.

Контракт:

- Числа конечные, без `NaN`/бесконечности/булевых значений. Единицы только сантиметры; конверсию выполнять отдельно с проверкой масштаба.
- Граница — простой многоугольник, препятствия — отдельные многоугольники. Толщины стен/несущие массивы включать в запретные объёмы, если это обосновано. Контур помещений без стен не эквивалентен внешнему контуру.
- `matrix`: квадратная симметричная матрица; `null` — нет ребра, положительное число — связь. Из родных весов-объектов преобразовывать наличие связи, не молча отбрасывать их.
- `geometry:"polyline"` разрешено только при подтверждённой форме рёбер. Для неизвестных кривых — `"unknown"`; хорда не подтверждает путь кривой.
- `allow_exterior:true` — только для явно разрешённой наружной части инженерной системы; не использовать для подавления дефекта обычной проводки. Проверка препятствий сохраняется.
- `anchor_id` — конкретный механизм/подключение из `points`, не центр рамки вместо центра механизма.
- Высоты проверяются только для заданной `role` и `preferences.heights_cm[role]`. Их происхождение — условие конкретного проекта, не ПУЭ.
- `preferences.door_clearance_cm` применяется к `role:"switch"`: расстояние **от переданной точки центра до ближайшего заданного отрезка проёма**. Это не измерение от края рамки/наличника. Для пользовательского зазора от рамки нужна отдельная геометрия и дополнительная проверка.
- Касание границы/препятствия отмечается консервативно, без разрешения проходки.

## Запуск

Из корня репозитория:

```sh
python3 remplanner-browser/scripts/audit_geometry.py normalized.json
python3 -m unittest discover -s tests -v
```

Скрипт только читает локальный вход, ничего не сохраняет и не подключается к сети. stdout — JSON с `scope:"geometry_only_not_compliance"` и находками `{code,status,subject,detail}`. Код выхода: `1` при FAIL, `2` при UNKNOWN без FAIL либо неверном входе, `0` только если переданные проверки прошли. Код 0 **не означает нормативную или монтажную пригодность**.

Защитные лимиты: вход до 10 MiB, глубина JSON до 32, до 100 000 узлов; целочисленный литерал до 128 цифр без знака (проверяется до преобразования в число). Коллекции ограничены 128 записями, многоугольник — 256 вершинами, граф — 128 вершинами и 512 рёбрами. Есть общий предел работы геометрической проверки; превышение даёт UNKNOWN, а не частичный PASS. Это диагностический инструмент для ограниченных наборов, не потоковый обработчик произвольных больших планов.

## Чего этот скрипт не проверяет

Нагрузки, сечения, автоматы/УДТ, заземление, зоны ванной, юридическую применимость, водяные уклоны/высоты, 3D-сервисный объём, мебель/дверные рамки, пожарную проходку, параметры стен, native-импорт/экспорт и фактический монтаж. Нельзя заменять этими тестами domain-проверки. В отчёте отдельно перечислить охват и недостающие проверки.
